# MySearchEngine

Локальная высокопроизводительная поисковая система на языке C++17 для полнотекстового поиска по массивам неструктурированных текстовых данных (.txt) с функцией интеллектуального исправления опечаток на русском и английском языках (метрика Дамерау-Левенштейна).

Разработано в рамках дисциплины **«Технологии индустриального программирования»** (Практическое занятие №2: «Сбор требований и архитектурная документация SRS»).

---

## 1. Бизнес-цели и концепция

* **Бизнес-цель (BR-1):** Ускорение поиска информации по текстовым файлам, с исправлением опечаток. Сокращение времени пользователя на ручной поиск данных в локальных текстовых архивах благодаря быстродействию поискового движка и отказоустойчивости к опечаткам на русском и английском языках.
* **Критерии успеха (BR-2):** Время отклика поискового движка на запрос не превышает 50 миллисекунд; мгновенная локальная выдача сниппетов и путей к файлам.
* **Бизнес-ограничения (BR-3):** Разработка ведется без использования сторонних СУБД (PostgreSQL, SQLite) или коммерческих полнотекстовых библиотек (Lucene, Elasticsearch). Все структуры (инвертированный индекс, расчет расстояния редактирования) реализованы независимо на чистом C++17/STL.

## 2. Сценарий работы пользователя и управление индексацией

* **Режим индексации:** Индексация **не происходит автоматически** при запуске или просто при указании директории. Она инициируется **строго по команде пользователя (`rescan`)**.
* **Сценарий пользователя:**
  1. Пользователь запускает приложение `MySearchEngine` и переходит в интерактивную консоль (REPL-интерфейс).
  2. Пользователь указывает путь к целевой рабочей директории с текстовыми файлами.
  3. Для первичной индексации пользователь вводит команду **`rescan`**. Происходит рекурсивный обход директории, чтение файлов `.txt` и построение инвертированного индекса в RAM.
  4. Пользователь вводит поисковые запросы, получая отсортированные по релевантности документы с контекстными сниппетами и автоисправлением опечаток.
  5. **Актуализация каталога:** Если файлы в рабочей папке были изменены, добавлены или удалены, пользователь в любой момент вводит команду **`rescan`** — система выполняет полную переиндексацию и актуализирует индекс без необходимости перезапуска программы.
  6. Пользователь вводит `:q` или `exit` для завершения работы.

## 3. Пути пользователя (User Journeys)

1. **1-й путь пользователя (Поиск):** Непрерывный интерактивный ввод поисковых запросов в цикле REPL без перезапуска приложения (`UR-1`).
2. **2-й путь пользователя (Автоисправление):** Поиск информации с интеллектуальным исправлением опечаток (нечеткий поиск при несовпадении термов по метрике Дамерау-Левенштейна) (`UR-2`).
3. **3-й путь пользователя (Выдача):** Просмотр списка результатов, ранжированных по релевантности (частота вхождений слова в документ), с абсолютными путями к файлам и превью-сниппетами (до 3 предложений) (`UR-3`, `UR-5`).
4. **4-й путь пользователя (Индексация и переиндексация) [Must Have]:** Указание пути к директории и ручной запуск индексации по команде `rescan`. Поддержка полной переиндексации: удаление, добавление и изменение документов (`UR-4`).
5. **5-й путь пользователя (Завершение):** Штатное завершение работы программы по управляющей команде `:q` или `exit` (`UR-6`).

## 4. Спецификация требований (по К. Вигерсу)

### Пользовательские требования (User Requirements, MoSCoW)
* **UR-1 [Must Have]:** Интерактивный ввод поисковых запросов в терминале (REPL).
* **UR-2 [Must Have]:** Исправление опечаток в запросах с уведомлением «Возможно, вы имели в виду: ...».
* **UR-3 [Must Have]:** Ранжирование результатов по релевантности (Term Frequency).
* **UR-4 [Must Have]:** Индексация и переиндексация по команде `rescan` с поддержкой удаления, добавления и изменения документов.
* **UR-5 [Should Have]:** Вывод абсолютных путей к файлам и контекстных сниппетов (до 3 предложений).
* **UR-6 [Must Have]:** Завершение работы программы по команде `:q` / `exit`.

### Функциональные требования (Functional Requirements)
* **FR-1:** Сканирование файловой структуры по команде `rescan` (обход каталога, определение новых, измененных и удаленных файлов `.txt`).
* **FR-2:** Лингвистическая предобработка текста (токенизация, очистка пунктуации, разбиение на предложения, регистронезависимость UTF-8).
* **FR-3:** Построение и перестроение инвертированного индекса в RAM (актуализация словаря, постинг-листов и хранилища при повторном `rescan`).
* **FR-4:** Поддержка REPL-цикла и командного диспетчера (команды директории, `rescan`, поисковые фразы, выход `:q`).
* **FR-5:** Автоисправление опечаток методом динамического программирования (порог расстояния $\le 2$).
* **FR-6:** Ранжирование совпадений и извлечение сниппетов.

### Нефункциональные требования (Non-Functional Requirements)
* **NFR-1 (Архитектура):** Соблюдение принципов SOLID, изоляция ответственности классов.
* **NFR-2 (Производительность):** 
  - Поиск слова в инвертированном индексе за время $O(1)$.
  - Время ответа на запрос $\le 50$ мс.
  - **- [ ] Полная переиндексация (удаление, добавление, изменение):** высокая скорость актуализации данных по команде `rescan` без перезапуска приложения и без утечек памяти.
* **NFR-3 (Память):** Оптимизация памяти при расчете расстояния Дамерау-Левенштейна $O(\min(M, N))$.
* **NFR-4 (Надежность):** Устойчивость к сбоям при чтении некорректных файлов, пустых запросов и невалидных путей (Crash-free).
* **NFR-5 (Локализация):** Полная поддержка русского (кириллица) и английского алфавитов в UTF-8 (`std::wstring`, `ru_RU.UTF-8`).
